# Godot 社区 AI 源码复用与集成计划

> 当前策略：所有社区源码快照默认关闭且不参与 Godot 构建。`agent_debugger` 本身也默认关闭，使用 `module_agent_debugger_enabled=yes` 显式启用。后续每项社区能力应作为独立 Adapter 按需移植和启用。

## 1. 决策

本项目不重复实现社区已经成熟的 Godot 编辑器控制、MCP 传输、Debugger Bridge、Runtime Probe、UndoRedo、权限配置和基础测试能力。

总体策略为：

```text
社区成熟实现
→ 固定上游 Commit
→ 保留许可证和来源
→ 以 Adapter 隔离上游接口
→ 增加本项目测试
→ 只修改必要部分

本项目原创实现
→ Trace Schema
→ Runtime Semantic Trace
→ Failure Window
→ Causal Graph
→ Root Cause Ranking
→ Patch Attribution
→ Deterministic Replay
→ Transactional Verification
```

社区项目当前均保存在 `sources/` 下。该目录作为上游源码快照，不直接加入 Godot 主构建。

## 2. 建议直接复用的源码

### 2.1 第一优先级：Godot-MCP-Native

上游：`yurineko73/Godot-MCP-Native`

建议直接复用：

- `mcp_debugger_bridge.gd` 的 EditorDebuggerPlugin 会话管理；
- EngineDebugger Message Capture Prefix；
- Break/Resume/Stop 状态；
- Stack、Scope、Variable 和 Debug Execution Control；
- `mcp_runtime_probe.gd` 的运行时通信结构；
- HTTP MCP Server 和 Bearer Token 鉴权；
- Project Test Runner；
- Render Screenshot Regression；
- Batch Node/Scene UndoRedo。

本项目扩展：

- 增加 Agent Trace Message Prefix；
- 将 Runtime Probe 从“当前状态查询”扩展为“事件历史采集”；
- 增加 `session_id`、`patch_id`、`event_id` 和 `parent_event_ids`；
- 增加 Failure Window 和 Snapshot；
- 把传统 Stack/Variable 接口包装为对象级和调用级语义查询。

### 2.2 第一优先级：hi-godot/godot-ai

上游：`hi-godot/godot-ai`

建议直接复用：

- Python FastMCP Server 的整体结构；
- Typed Protocol Envelope；
- WebSocket Session Registry；
- 多 Editor Session 路由；
- Tool Domain Rollup；
- Structured Error 和错误建议；
- `batch_execute` 与 UndoRedo Rollback；
- Editor/Game Log Buffer、`run_id` 和 Cursor；
- Game Helper Liveness；
- Test Runner；
- Circuit Breaker、Timeout 和 Origin Guard；
- 单元和集成测试组织方式。

本项目扩展：

- 在 Envelope 中加入 Trace Context；
- 将 Log Cursor 扩展成版本化 Trace Cursor；
- 增加 `query_failure_window`、`query_object_history` 和 `rank_root_causes`；
- 把 Batch Undo 升级为 Patch Transaction；
- 将行为、性能和资源完整性验证绑定到 Patch。

### 2.3 第二优先级：Erodenn/godot-mcp-runtime

上游：`Erodenn/godot-mcp-runtime`

建议直接复用：

- 临时 Autoload Runtime Bridge 注入；
- Bridge Artifact 创建和清理；
- Background/Attach 模式；
- Runtime Screenshot；
- Input Simulation；
- UI Discovery；
- Headless Operation；
- Path Validation 和危险脚本扫描；
- Runtime Tool 测试框架。

本项目扩展：

- 将临时 Bridge 用于隔离验证和有限重放；
- 禁止 Agent 任意执行 Live GDScript；
- 改用类型安全 Observation Probe；
- 为输入、随机种子、时间步和异步完成事件生成 Trace。

### 2.4 第二优先级：AI Assistant Hub

上游：`FlamxGames/godot-ai-assistant-hub`

建议直接复用或移植：

- Allow/Ask/Hide 权限模型；
- 每个 Agent 独立 Tool Access Profile；
- Tool Option；
- 隐藏无关工具以减少上下文；
- 文件、节点属性和关键字范围限制；
- Tool Undo 接口。

本项目扩展：

- Tool Access Profile 升级为 Capability Manifest；
- 使用 UUID/单调序列生成操作 ID；
- 权限范围覆盖目录、资源、场景、运行预算和性能预算；
- Undo Queue 升级为多文件、多资源事务。

### 2.5 第二优先级：tomyud1/godot-mcp

建议直接复用或改造：

- Project Map；
- Script Relationship Graph；
- Find Usages；
- Scene Graph Explorer；
- Browser Visualizer 通信和交互模式。

本项目扩展：

- 图节点改为 Patch、Object、Resource、Invocation、Signal、State 和 Failure；
- 图边区分直接因果、推断因果和时间相邻；
- 支持从 Failure 向上游折叠查询；
- 支持 State Diff 和证据面板。

### 2.6 可选择复用：Golem-AI

建议移植：

- Core/Full Harness；
- Minimal Bootstrap；
- 按需项目索引；
- Skills；
- Anti-hallucination Guard；
- 完成前强制验证。

这些能力属于外部 Agent Orchestrator，不应进入 Godot Runtime Core。

## 3. 不建议直接复用的部分

- 无鉴权的 Localhost HTTP Server；
- 直接调用 `node.set()` 且不进入 UndoRedo 的写操作；
- 任意 Live GDScript 执行；
- 依赖自然语言日志解析建立因果关系；
- 仅用毫秒时间作为操作 ID；
- 只按文件名保存 Backup；
- 平铺暴露 100～175 个 MCP Tool；
- 仅依靠截图相似度判断行为正确；
- 把编辑器 UndoRedo 当成完整 Patch Transaction；
- 只检查项目是否启动就声明修复成功。

## 4. 推荐集成目录

不要直接在社区快照中开发。建议建立：

```text
thirdparty/agent_tools/
├── godot_mcp_native/
├── godot_ai_control_plane/
└── LICENSES/

modules/agent_debugger/
├── adapters/
│   ├── mcp_native_adapter.*
│   ├── godot_ai_adapter.*
│   └── runtime_bridge_adapter.*
├── trace/
├── causal/
├── state/
├── replay/
└── validation/

tools/agent_debug/
├── control_plane/
├── orchestrator/
└── visualizer/
```

其中：

- `sources/`：只读研究快照；
- `thirdparty/agent_tools/`：实际进入项目的固定版本上游代码；
- `adapters/`：隔离上游 API 和本项目协议；
- `modules/agent_debugger/`：本项目核心原创实现。

## 5. 上游代码进入项目的流程

每次复用必须记录：

```text
upstream_repository
upstream_commit
upstream_license
import_date
imported_paths
local_changes
local_owner
```

推荐流程：

1. 从 `sources/` 选择具体文件；
2. 在 `THIRD_PARTY_NOTICES.md` 登记仓库、Commit 和许可证；
3. 复制到 `thirdparty/agent_tools/<component>`；
4. 保留原文件版权头；
5. 对本地修改使用独立 Commit；
6. 通过 Adapter 接入，不让引擎核心依赖上游内部类型；
7. 增加本项目契约测试；
8. 上游升级时使用独立合并或重新导入流程。

## 6. 许可证要求

本次选定快照均包含 MIT License。MIT 通常允许使用、复制、修改、合并、发布和再许可，但要求在软件的重要部分保留版权声明和许可证文本。

工程上至少需要：

- 保留各上游 `LICENSE`；
- 建立 `THIRD_PARTY_NOTICES.md`；
- 复制源码时保留现有版权头；
- 在二进制或发布包附带的许可证集合中包含对应 MIT 文本；
- 修改过的文件明确记录本地修改，不冒充完全原创；
- 每次更新重新检查上游当前许可证。

这是一套工程合规建议，不替代正式法律意见。

## 7. 推荐的第一批实际复用

第一批不要一次性合并整个插件，建议只导入四个纵向切片：

### Slice A：Debugger Transport

```text
Godot-MCP-Native Debugger Bridge
→ 自定义 agent_trace Message Prefix
→ 外部 Trace Consumer
```

### Slice B：Trace Session Transport

```text
hi-godot Envelope + Session Registry + Cursor
→ Trace Session API
→ Failure Window Export
```

### Slice C：Transactional Editor Mutation

```text
hi-godot Atomic Batch
+ MCP-Native UndoRedo
+ AI Assistant Hub Capability Profile
→ Patch Transaction v0.1
```

### Slice D：Isolated Runtime Validation

```text
godot-mcp-runtime Transient Bridge
+ Native Test Runner
+ Screenshot Regression
→ Headless Behavior Validation
```

完成这四个切片后，再开始 Causal Graph 和 Root Cause Ranker。这样可以最大限度利用社区代码，同时保持本项目原创研究边界清晰。

## 8. 原创研究边界

为了保证后续论文和研究贡献清晰，建议把以下部分明确标记为本项目原创：

- Godot Agent Debug Trace Schema；
- 游戏语义因果边定义；
- Failure Window 生成算法；
- Object/Resource/Invocation 历史模型；
- State Snapshot/Diff 规范；
- Top-k 多根因排序；
- Targeted Instrumentation Planner；
- Replay Budget Scheduler；
- Patch Attribution 和 Evidence Graph；
- 行为、性能与资源完整性联合事务；
- Godot Agent Debug Benchmark。

社区代码解决“如何连接和操作 Godot”，本项目解决“如何让 Godot 为 Agent 产生可解释、可验证、可恢复的调试证据”。
